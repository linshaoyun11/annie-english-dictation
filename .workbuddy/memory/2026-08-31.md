# 2026-08-31 工作日志

## 默认键盘（英文小写全键盘）问题：根因定论 + 决策

### 关键发现（推翻此前所有修复的前提）
- **`inputmode="latin"` 不是合法值**。WHATWG inputmode 规范只有 8 个值：none / text / tel / url / email / numeric / decimal / search。`latin` 来自 2015 年前被删除的旧草案，Chrome 与 Safari 从未实现。
- 因此 `src/components/SpellingInput.tsx` 的 `applyKeyboardAttributes()` 里这一行**一直是 no-op**，浏览器遇到非法值直接回退默认。
- 推论：build 38/42/44/47 四轮围绕它的修复（ref callback 提前 setAttribute、blur + 双 rAF + focus 重评、composition 检测重评）**全部建立在无效前提上**，属于无效劳动。这也解释了为什么"具体出现情形无法确定"——它从来没有生效过，观察到的波动纯粹是系统随机行为。

### 系统层事实（查证来源）
- Apple《Text Programming Guide》：键盘语言由用户语言偏好决定，**无法用代码强制**。
- 原生唯一的救命稻草 `UIResponder.textInputMode` 重写（可指定已启用的键盘语言）——StackOverflow 明确记录**对 WKWebView 无效**（底层 WKContentView 无法被覆盖，swizzling 也失败）。
- Microsoft SwiftKey 官方支持文档：第三方键盘"锁定设备后返回 app / 切 app 时"会回落到 Apple 默认键盘，官方给的解法全是用户侧（把键盘拖到列表首位、重启手机、手动点 globe 键）。连拥有原生键盘扩展权限的厂商都做不到，WKWebView 更不可能。

### 结论
iOS 键盘语言是系统级状态，Web 层不可写。此问题**不可通过代码修复**。

### 三个可选方向（待用户决策）
1. **放弃 + 清理死代码**（推荐）：移除 blur/rAF/refocus 无效逻辑，保留 autocapitalize/autocorrect/spellcheck/lang；检测到中文输入法时给一次性轻提示引导用户切键盘。
2. **自绘 A–Z 键盘**：input 设 `readonly` 彻底屏蔽系统键盘，页面内渲染自己的字母键盘。100% 确定、永远英文小写，代价是开发量 + 失去原生键盘手感（iPad 上观感偏怪）。
3. **兼容中文输入法**：监听 `compositionupdate` 取拼音原始字母喂给拼写逻辑，让中文键盘下也能答题。中等工作量，空格/候选词提交有冲突风险。

### 已实现方案（本地完成，未推送）
`src/components/SpellingInput.tsx` 全量重写：
- **彻底移除真实 `<input>`**（无 input 就不会唤起系统键盘），改为页面内自绘 QWERTY 小写字母键盘。行为 100% 确定，不受 iOS 键盘语言记忆/回落影响。
- 键盘布局：3 行（10 / 9 / 7+退格），第 2、3 行两侧 `basis-0 flex-[0.5]` 留白与首行 10 键对齐；容器 `max-w-[420px] mx-auto`，托盘 `bg-primary-lighter`、键 `bg-white`、`active:scale-[0.94]` 反馈。
- **物理键盘兼容**：window 级 keydown 收字母/退格；检测到硬件按键后置模块级 `hardwareKeyboardSeen = true` 并自动收起屏幕键盘（跨题目保持），提供"使用屏幕键盘"唤回入口与"隐藏屏幕键盘"链接。
- 退格支持长按连续删除（立即删 1 个，400ms 后每 110ms 续删），用原生 setTimeout/setInterval（不用 safeTimeout，避免冻结补发导致误删）。
- 顺带删掉的代码：blur + 双 rAF + focus 重评、中文输入法 composition 重评、inputKey 后台重建僵尸 input、onDocClick 聚焦、visibilitychange 处理、applyKeyboardAttributes。组件从 551 行降到约 420 行。

`src/components/LearningCard.tsx`：
- 移除 `h-0 w-full` 常挂载 hack，改为 `{!completed && !revealed && (<div className="mt-7 w-full">…)}`——答对/揭示后整块卸载让出空间。
- 更新 soundwave 容器 onMouseDown 注释（原"防止抢焦点导致键盘收起"已不适用）。

## 键盘条改为固定贴屏幕最底部（本地完成，未推送，待 build 48）
用户反馈：自绘键盘应像系统键盘一样固定在页面最底部，而不是跟在字母格后面的文档流里。

`src/components/SpellingInput.tsx`：
- 新增 `import { createPortal } from "react-dom"`，键盘条用 portal 挂到 `document.body`，`fixed inset-x-0 bottom-0 z-30`，`border-t + bg-primary-lighter + 上投影`，`paddingBottom: env(safe-area-inset-bottom)` 避开 Home 指示条。
- z-30 低于祝贺页遮罩 z-40，庆祝弹层仍能盖住键盘条。
- 新增 `barEl` state（ref 回调 `setBarEl`）+ effect：用 `getBoundingClientRect().height` 实测高度写入 CSS 变量 `--dkb-h`（ResizeObserver + window resize 双保险），卸载时归零 `0px`。
- 收起态（检测到物理键盘）不再是一个内联按钮，而是同一条底部条里的"使用屏幕键盘"胶囊，位置一致、不跳动。
- 新增 `answering = !done && !revealed` 统一控制字母格与底部条。

`src/components/LearningCard.tsx`：
- 根容器 padding-bottom 改为 `calc(var(--kb-h,0px) + var(--dkb-h,0px) + theme(space.6))`，内容区自动避让，"我不会"按钮不会被键盘条盖住。
- 更新拼写输入层注释。

校验：tsc -b --noEmit 通过；oxlint 全量 0 error（仅 2 个既有的 RoundsStars fast-refresh 警告）。dev server 已起在 5180 预览。
