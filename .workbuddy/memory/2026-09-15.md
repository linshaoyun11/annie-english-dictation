## 音频修复（build 114）—— 用户报「"a" 词条音频不对」
- **根因链**：build 108 的豆包批次按 `dump_all_texts.mjs` 导出文本重生成，而该脚本
  **用 `toLowerCase()` 做去重键** ⇒ ① 大小写信息丢失；② 判据「拼读型」（音标含 ≥2 个
  字母名）覆盖面过宽。三类影响：
  1. **单个跑飞**：豆包对极短输入自回归跑飞。用户报的 `a` 英音 **2.71s**（正常 0.99s）、
     美音 1.27s；另抓到 5 条：`to go` 美 8.09s/17 声段、`along with sb` 美 7.70s、
     `at the end of` 美 5.54s、`junior high` 英 4.32s/7 段、`weld quay` 美 2.09s。
  2. **拼读→整词回归**：build 104/107 刚修好的缩写字母读法被覆盖成整词读。
  3. **同形异读冲突**（结构性，见下）。
- **修复手法**：
  - `a` 美/英 + 5 条跑飞 → 从 `.workbuddy/tmp/pre108-full/`（git `8aa32f5^` 解出的
    pre-108 快照）恢复。`a` 恢复后美 0.89s / 英 0.96s 单声段，与有道原始字节一致。
  - 判据演进（重要）：**「活跃语音时长」被 build 111 的响度归一搞坏**——归一放大了底噪，
    `a` 英音总时长 0.99s 却报 active=1.95s（>总时长，荒谬）。改用**声段数**
    （能量包络连续有声段个数）才干净利落：`to go` 现网 17 段 vs 正常 2 段。
  - ⚠️ **音标判据噪声极大**：`Chinese` 里的 `aɪ`/`iː`、短语里的冠词 `a`（音标写作 `eɪ`）
    都会被「字母名」正则误命中。22 条清单里经音频实测只有 **4 条**是真回归
    （`it`/`us`/`am`/`who`，时长掉到 0.43~0.61 倍），其余 18 条时长相当 —— **别凭音标回滚**。
- **结构性修复：查表区分大小写**（本 build 的重点）
  - 冲突对：`IT`(信息技术) vs `it`(它)、`US`(美国) vs `us`(我们)、`AM`(上午) vs `am`(是)、
    `WHO`(世卫组织) vs `who`(谁)。**数据里大小写本来就是区分的**，是哈希/查表把它抹平了。
  - 历史包袱：用户 **2026-09-13 就报过「US 读成"我们"、WHO 读成"谁"」**（build 104），
    所以**不能简单改回单词读**（那会重犯旧错）——必须两侧各有音频。
  - 做法：`src/lib/audio.ts` 查表改「**原样键优先 → 小写兜底**」，缓存键同步改原样文本
    （否则 `it`/`IT` 撞缓存）；两份 manifest 加 8 个大写键；`regen_audio_by_text.py`
    的 `fname()` 去掉 `lower()`（小写文本哈希不变 ⇒ 存量文件名/manifest 全兼容）。
  - 素材零合成造假：大写拼读版直接**复制** build 104/107 已核验的文件（`it`/`am` 取自
    pre-108 快照，`us`/`who` 现网未被 build 108 动过）；小写 `it`/`us`/`who` 用有道重取
    单词读音；`am` 现网已是豆包单词读，保留。
  - 8 个大写文件原为 Edge 输出，比全库基线轻 5~7dB ⇒ 用 build 111 的管线归一
    （美 −13.47 / 英 −15.01 dBFS，峰值保护 −1.0 dBFS），实测落到 −13.9~−16.2 / −14.8~−15.5。
  - `src/data/renjiaoSL.ts` 修 4 条**自相矛盾**的音标（音标说字母、释义说是词，或反之）：
    `it/它`→/ɪt/、`who/谁`→/huː/、`IT/信息技术`→/ˌaɪ ˈtiː/、`AM/上午`→/ˌeɪ ˈem/。
    ⚠️ 这 4 条是推断（释义为准），若用户课本截图另有写法需回退。
- **同步修掉的三处脚本隐患**（否则下次重跑复发）：
  - `dump_all_texts.mjs` 去重键 `toLowerCase()` → 原样文本（**这是根因**）
  - `doubao_tts_batch.py` fid 解析改为与 App 端同构（原样 → 小写兜底）
  - `regen_audio_by_text.py` `fname()` 去 `lower()`（并补注释说明为何不能 lower）
- **判据再次踩坑（第 4 次）**：魔数校验写成 `buf[:3] in MAGIC`，而 `\xff\xfb` 是 2 字节 ⇒
  永远为假。必须**按各自长度前缀比对**（`any(buf[:len(m)] == m for m in MAGIC)`）。
  另：`ok_mp3()` 里带 `len>=1024` 却只喂 4 字节入参，也会假失败 —— 长度与魔数要分开判。

## 页面顶部栏吸顶（build 115，用户要求「下滑时返回/标题/头像固定在顶部」）

- **做法**：新增 `src/components/PageTopBar.tsx`，三页（设置 / 用户资料 / 重点记忆）
  共用 —— 三页的顶部栏结构逐字相同（`<div className="flex items-center gap-3 pt-8">`），
  不抽组件就得把同一套滚动监听抄三遍。
  - `sticky top-0 z-20 -mx-5 bg-bg px-5 pt-8`：父级滚动容器带 `px-5`，
    `-mx-5 px-5` 把**背景**铺到容器左右边缘（否则内容从两侧 20px 缝里露出），
    内容仍保持 20px 内缩 ⇒ 未滚动时版面与改前逐像素一致（已实测，见下）。
  - 靠向上查找最近的 `overflow-y:auto|scroll` 祖先监听 scroll；`stuck` 只在跨过
    2px 阈值那一刻 setState，**不随每帧滚动重渲染**。
  - 下沿分隔 = `inset 0 -1px 0 rgba(83,74,183,.10)` 发丝线 + `0 8px 16px -10px
    rgba(83,74,183,.35)` 投影，**只在 stuck 时出现、且全用 box-shadow**（不占布局）
    ⇒ 出现/消失不会把内容顶动 1px。静止在顶部时没有这道线，首屏观感零变化。
  - `data-topbar` 属性留作探针/测试钩子（同 `data-dictation-keyboard` 的先例）。
  - `z-20` < 「关于」弹窗 `z-50`，弹窗仍盖住顶栏。

  —— 浏览器里真的把滚动容器滚到指定位置再截视口（静态全页截图验证不了 sticky）。
  探针 `probe-settings.html` / `probe-difficult.html`（`?mode=old` 用注入 CSS 把

    「设置」字形边缘（区域平均色 132.9 vs 132.5）＝ **抗锯齿差异，非位移**。
  - 滚动 670px：改前顶栏完全滚出屏，改后固定。
  - 用户资料页列表态内容不满一屏（scrollHeight == clientHeight == 844）⇒ 吸顶无观感影响。

### 补丁：分隔线与头像之间留空白（build 116，用户反馈）

- 用户看预览后指出「分割线跟头像之间请留一点空白」—— 36px 的圆按钮**圆底正好压在发丝线上**。
- 做法：顶栏加 `pb-3 -mb-3`（12px，**成对出现**）。负 margin 抵消 padding 对流内占位的影响：
  相邻 margin 塌陷后 `28 + (−12) = 16px`，盒底由 68 落到 80，相加仍是 96
  ⇒ 下方内容 y 坐标**一个像素都没动**（实测 scrollTop=0 前后差异 **0 像素**、
  `scrollHeight` 仍 1514）。发丝线现在在 y=79（头像底边 y=68 → 11px 纯空白 + 1px 线）。
- **不要**改成「只在 stuck 时加 pb-3」：那会让顶栏盒高在滚动的一瞬间长高 12px，
  底部 12px 内容突然被盖住，出现一次可见跳动。
