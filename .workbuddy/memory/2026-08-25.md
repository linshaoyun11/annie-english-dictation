## 文件消失事件根因排查（修正之前"安全软件"的错误结论）
- 用户反馈本地无杀毒软件，要求排查是否 AI 自行删除。通过解析回收站 $I 元数据（~/.workbuddy/tmp/parse_recycle.py）完成取证：
- **真相**：是 WorkBuddy 沙箱的安全删除层（Temp 下 codebuddy-safe-delete-bulk\<hash>\ 痕迹）拦截了 git 的文件删除/替换操作，改为整目录移入回收站。00:53:22/30（git revert 0ad433e 时刻）src\lib（7 文件）和 src（26 文件）被整体移入回收站，git 只回写了 revert 涉及的 3 个文件，其余 30 个未重写 → 从磁盘消失。**文件一直在回收站，未真正丢失**（git restore 已恢复）。
- 该机制同时解释了两大旧谜团：
  1. `.git/refs/remotes/origin/main` 反复消失：每次 git push/fetch 都会删写该 ref，安全删除层将其移入回收站（回收站有几十条 origin\main 记录，与历次 push 时间一一对应），偶发回写失败即"引用消失"。
  2. vite build "safe-delete ETIMESOUT"：dist（100MB/5200 文件）被移入回收站导致超时。
- 结论：不是杀毒软件，也不是有意删除；是沙箱 safe-delete 层在 git 大批量文件操作时的过度删除/回写失败 bug。建议用户向 WorkBuddy 反馈。风险缓解：文件实际进回收站可恢复；重要操作前确保已 commit。

## 后台唤醒输入不跳转 + 无声音修复（commit 5748844）

### 问题1：输入完成后不自动跳转（密码框 + 学习页）
- 根因：后台唤醒后 WebKit 定时器冻结，safeTimeout 心跳只在后续用户交互时补发；但输完最后一个字符后没有更多交互，提交/跳转回调永不执行。
- 修复：
  - SpellingInput: 新增 typedRef 同步镜像 typed 数组，pushLetter 中同步检测完成并直接调 onComplete，不再依赖 useEffect 重渲染（冻结时可能不触发）。popLetter/handleChange/reveal 也全部改用 typedRef 保持同步。
  - PasswordModal: handleChange 中输完4位直接 submit(clean)，去掉 safeTimeout 150ms 延迟。
  - ProfilePage: handlePwdInput 同上改法。
- 注意：safeTimeout 在其他场景（错误密码 shake 等）仍保留，因为后续有用户交互能触发心跳补发。

### 问题2：后台唤醒后无声音
- 根因：原生 AppDelegate.applicationDidBecomeActive 里 activateAudioSession() 在后台队列异步执行，JS visibilitychange 同时触发 play()，此时音频会话尚未就绪，play() 静默失败。切一次 APP 再回来时会话已就绪所以有声。
- 修复：useSpeechLoop 的 visibilitychange→visible handler 中，音频模式恢复改为延迟 500ms（safeTimeout）再 playCurrent，给原生会话激活足够时间。safeTimeout 即使冻结，心跳也会在后续用户交互时补发。

## WebAudio ELEMENT:DECODE 根因修复：剥离 ID3v2.4 标签（待真机验证）
- Build 28 实测显示 ELEMENT:DECODE → decodeAudioData 解码失败，**WebAudio 路径自 build 23 起在真机从未成功过**（每次静默回落 Element，所以首播小声一直都在；build 27 的"WEB"是 tryWrapElement 假标签）。

## Build 31：僵尸 ctx 重建 + 首播非零噪声预热（commit 8b5a8ef）
