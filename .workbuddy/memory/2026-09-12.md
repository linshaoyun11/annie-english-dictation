## 自动跳题失效排查与三路兜底加固（20:07–20:45，APP_BUILD 92）
- 用户真机：答对页进度条走完不自动跳题。桌面无头复现（自绘键盘逐键点击真实拼写）

- 复现环境副产物：?preview=grade 会 previewCelebration 强弹年级通关祝贺 ⇒
  frozen=true ⇒ handleComplete 提前 return 不建定时器，而进度条 span 的渲染条件
  是 completed&&autoNext 与 frozen 无关 ⇒ **「进度条走但永不跳」的精确复现机制**。
  （另外 preview 用户进度会落盘 preview-user，跨会话残留，repro 前要 localStorage.clear）
- 根因判定：timer.ts 顶部早有记载的 iOS WebKit「后台挂起后 JS 时钟冻结」——
  表现即「答对不自动跳题，重启才恢复」。冻结态下 safeTimeout 死、animationend
  兜底不可靠（派发依赖主线程任务队列），且自动跳转窗口内无用户触摸 ⇒ runKicks
  心跳无从补发。进度条是合成器 CSS 动画照走 ⇒ 用户看到「走完不跳」。
- 修复（三路互斥兜底）：
  ① LearningCard 新增 autoNextDoneRef + fireAutoNext 统一出口；
  ② 新增 rAF 帧数兜底 effect：completed&&autoNext&&!frozen 时数帧，
     墙钟差≥1750ms 或 帧数≥200 触发（时钟正常走墙钟精确跳；时钟冻结靠帧数，
     120Hz≈1.7s / 60Hz≈3.3s）。渲染管线活着（进度条在走）⇒ rAF 活 ⇒ 必跳；
  ③ onAnimationEnd / 按钮手动跳过 / 空格 全部并入 doneRef 互斥；
  ④ goNext busyRef 加 try/finally：任何分支抛异常也释放，防永久卡死全部跳转。
- 验证：tsc 过；dev 复现正常路径 1800ms 跳题回归通过；临时把 safeTimeout 改
  60000ms 模拟时钟冻结，rAF 兜底独立跳题成功（1/31→2/31）；临时改动全部还原。
- 复现方法沉淀：无头 Edge + 自绘键盘逐键 pointerdown 拼词；键盘按钮文本是
  **小写**字母；React fiber 顺 return 链找 memoizedProps.entry 读当前词条。

## 自动跳题时长与进度条不符（20:57–21:15，APP_BUILD 93）
- 用户反馈：进度条走完的时刻和实际跳转对不上。根因：build 92 的 rAF 兜底
  **帧数阈值写死 200** —— 冻结态下墙钟判断失效只剩数帧，200 帧 @60Hz = 3.33s
  （比 1.8s 进度条晚 1.5s）、@120Hz = 1.67s（早 0.13s）。时钟正常的机器走
  墙钟路径（1750ms）无感，所以只在冻结态真机上暴露。
- 修复（LearningCard.tsx）：模块级 `cachedHz` 实测刷新率缓存——兜底循环前
  20 帧用 Date.now() 帧间隔实测 Hz（只认 2~40ms，冻结时 dt≈0 自动过滤），
  帧数阈值 = ceil(Hz×1.8)+8 帧余量；墙钟阈值 1750→1780ms 对齐进度条。
  首题即冻结且无缓存的罕见情形退回 200 帧（宁可慢不可不跳），第二题起即有缓存。
- 定量验证（.workbuddy/tmp/raf_sim.js 模拟）：时钟正常 1.78s；冻结+缓存
  60Hz 3.33s→**1.93s**、120Hz 1.67s→**1.87s**，均紧贴进度条 1.8s。tsc 过。
- 教训：**任何「用帧数换算时间」的逻辑都不能写死帧率**，ProMotion/60Hz 差一倍。
