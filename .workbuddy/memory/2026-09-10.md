## 音频库体积账（排查「为什么体积小这么多」）

用户问体积为何下降。查清后发现**我上一轮报的「412M → 194M」是误导**——那是
新旧文件并存的临时状态。用 git blob 精确统计的真实对比：

| | 旧库 eac36b4 | 新库 | 变化 |
|---|---|---|---|
| 文件数 | 15829（美 8014 / 英 7815） | 9730 | −38.5% |
| 体积 | 188.2 MB | 165.4 MB | **−12.1%** |
| 单文件 | 12.2 KB | 17.4 KB | +43% |

体积只降 12%（不是"小一半"）。文件数 −38.5% 与单文件 +43% 相互抵消。
- 降幅来源：① 文本哈希命名后同文本全局只存一份；② 清掉 5159 个孤儿文件
  （15829 − 10670，占 32.6%，历史词库重建留下的垃圾）。
- 单文件变大：新库没跑 optimize_audio.py，是音源原始字节。

## 判据坑 #3：PCM 互相关不能先 trim
trim 去静音后两段起点差几十样本，负 lag 落在循环卷积尾部，
只搜 `conv[:span]` 会漏掉 ⇒ 假低分 0.25（实际 0.99）。
修法：双向搜 `max(conv[:span].max(), conv[n-span:].max())`。
本项目连续三次栽在判据上（跨音源 → 小写 key → lag 搜索），
**结论：任何音频比对判据上线前必做自检**。

## 🔴 年级错乱（外研一线 / 牛津一线显示"初中1~12年级"，v24 修复，APP_BUILD 79）

### 用户报告
外研社一年级起点、牛津一年级起点两套的年级错乱（截图：初中1年级~初中12年级）。

### 根因
`waiyansheSL.ts` / `oxfordSL.ts` 按**教材册序号**填 grade（1A=1、1B=2、2A=3 … 9B=18，
文件头注释自证："G3 二年级上册 (2A)"、"G5 三年级上册 (3A)"）。
UI `gradeLabel`：grade≤6→"小学N"、>6→"初中(grade-6)" ⇒ 册 10-18 显示成初中4~12年级。
renjiao 正常是因为 renjiaoSL 本就按真实年级 3-9 编写。
（oxford = 沪教牛津上海版 1-9 年级 × 2 学期 = 18 册；外研一线同构 18 册。）

### 修复（curriculum.ts 组装层，不动 SL 源文件）
1. 新增 `mergeBooksToGrades()`：G=⌈册/2⌉，同年级内下册 unit 续接上册；
   entry 的 grade/unit/id 同步重写（id 只改 g/u 段、seq 保留，wy-/ox- 与无前缀都处理）；
   先按册号稳定排序（oxfordSL 里 3A/3B 排在 2A/2B 前面）。
2. waiyanshe 课标补全 midGrades [7..18] → [7,8,9]。
3. **连带坑**：dedupeEarlyGrades 的 seen 跨年级累计，把 2A 中复现 1A/1B 核心词的
   整单元错删（M3U1 mother/father…、M4U1 her/his…）——v23 同款坑再现。
   加 `perGrade` 参数（seen 同年级内累计、跨年级重置），waiyanshe 传 true；
   renjiao 保持原行为不动。
4. CURRICULUM_VERSION 23→24（id 全变 ⇒ freshProgress，积分保留）。
