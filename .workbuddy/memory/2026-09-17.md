# 2026-09-17

## 资料页新增「删除本用户」（含密码验证 + 二次确认）

**需求**（用户原话）：在用户资料页增加一个「删除本用户」按钮 → 点击后要输入密码 →
密码正确后弹提示框，提示会删除所有用户资料、积分、进度 → 确认后删除该用户 →
页面跳回初始页 → 创建新角色页里该用户选的小动物头像恢复为可选。

### 落点

| 文件 | 改动 |
|---|---|
| `src/lib/progress.ts` | 新增 `clearUserProgress(userId)` |
| `src/pages/ProfilePage.tsx` | 「危险操作」分组 + 密码验证（自绘 NumberPad）+ 二次确认弹窗；页面改两段式布局 |
| `src/App.tsx` | `handleDeleteUser`；`ProfilePage` 加 `onDeleteUser` prop |
| `src/components/Icons.tsx` | 新增 `TrashIcon`（与 KeyIcon 同规格） |
| `src/probe/profileProbe.tsx` | 补 `onDeleteUser`、加 `?step=del` 入口 |

### 几个设计决定（改之前先看）

1. **`clearUserProgress` 必须遍历全部教材线**。现有 `resetProgress(userId, version)` 只清单条
   —— 那对「清空学习进度」（只针对当前教材）是对的，但删除用户要清干净：用户在设置里可能
   切过教材，6 条线的进度是**独立存储**的。
   遍历用 `Object.keys(CURRICULUM_LABELS)`：它是 `Record<CurriculumVersion, string>`，
   将来加教材线 TS 会强制补全，漏不掉。
2. **头像是"自动"释放的，不需要写释放逻辑**。创建角色页的禁用判定是
   `takenAvatarIds(users)`，档案一从列表移除，该头像自然回到可选态。
3. **流程顺序与 HomePage 的「清空进度」相反**，这是用户明确要求的：
   - HomePage：先弹确认框 → 再验密码
   - 本页：**先验密码 → 密码对了才弹确认框**
4. **删除后跳 `select`（App 的初始 view）**，不跳 register。理由：字面贴合"初始页"，
   且 `UserSelectPage` 本来就有空态（"还没有小伙伴 / 点击下方按钮创建第一个角色吧"），
   删光了也不会卡住，底部「创建新角色」按钮常驻。
5. `setCurrentUser(null)` 与 `setView("select")` **必须在同一批更新里** —— 否则
   `currentUser` 先变 null 会让 `view === "profile"` 的分支渲染成空白。

### 页面结构：改成两段式

原来根容器是 `h-full overflow-y-auto px-5 pb-10`（整页一个滚动容器）。
密码键盘要参与布局，所以改成：

```tsx
<div className="flex h-full flex-col">
  <div ref={scrollRef} className="min-h-0 flex-1 overflow-y-auto px-5 pb-10">
    <PageTopBar>…</PageTopBar>
    …
  </div>
  {delStep === "auth" && <NumberPad … />}
</div>
```

- 键盘在**文档流内**（flex 第二行）⇒ 结构上不可能遮住密码卡片，不靠 `--kb-h`。
- **改密码流程保持原样**（系统键盘 + `--kb-h` padding），两套并存：
  `delStep` 非空才渲染 NumberPad，`pwdStep` 非空才用系统键盘。
  ⚠️ 这是页内的一处**已知不一致**：同一页两种数字输入方式。本次按"只做用户要求的功能"
  没动改密码流程（它在页面中部，没被键盘盖住的问题，一直没报障）。要统一的话另开一轮。
- 键盘展开后把密码卡片滚进视野：`scrollIntoView({block:"center"})`，
  套**两层 rAF**（布局变更与 scrollHeight 更新不同帧，同 RegisterPage）。
- 内置物理键盘兜底（数字键 + Backspace）：桌面预览与 iPad 外接键盘能用，
  也方便自动化测试。

### 验证（这次做得很足，删除是不可逆操作）

新增 `scripts/headless_edge_run.sh`（通用启动器）+ `scripts/test_delete_user.mjs`（e2e 回归）：

```bash
npx vite --port 5180 --strictPort                       # 终端 A
bash scripts/headless_edge_run.sh scripts/test_delete_user.mjs
VERIFY_W=375 VERIFY_H=667 bash scripts/headless_edge_run.sh scripts/test_delete_user.mjs
```

覆盖的断言（22 项，全过）：初始空态 → 建号 → 资料页出现「危险操作/删除本用户」→
自绘键盘展开 → **输错密码被拒且不弹框** → 输对密码弹确认框（文案含"资料/积分/学习进度"、
键盘已收起）→ **点取消不删档** → 重走并确认删除 → 跳回初始页 → 档案从 localStorage 消失 →
**所有教材线的进度键清空**（测试里专门埋了一条 renjiao 线来验这一点）→ 无残留 userId →
创建角色页「小狗」`disabled=false`（头像已释放）。

版式另跑三视口 × 两态（375/390/428）无横向溢出；375×667 走完整流程同样全过。

### 踩的坑

1. **`python -c` 在这个 shell 里会挂起**（2 分钟无输出、无 stderr，被自动后台化）。
   上次会话它还能用，这次不行。⇒ 文本批处理改用 `node -e`。
2. **探针里 dispatch 合成 keydown 自动输密码，在无头环境不可靠**。
   实测：手动发单个 keydown 有效（监听正常），但探针 `useEffect` 里那段递进输入不发火。
   已把 `?pwd=` 参数去掉，并在探针注释里写明"要验完整链路就跑 e2e 脚本"。
   别在探针里加自动交互。
3. **`handle.page()` 在 puppeteer-core 新版不存在**（旧版有）⇒ 显式把 `page` 传进辅助函数。
4. **密码错误提示只亮 500ms**（与全站一致）⇒ e2e 里最后一位必须点完立刻断言，
   否则等 `typeOnPad` 的内置间隔走完提示已复位，会被误判成失败（第一版就栽在这）。
5. 同一个启动器脚本**连着跑两次**（`bash A && bash B`）会有竞态：前一个收尾的
   `taskkill msedge` 可能打掉后一个刚拉起的浏览器（报 ProtocolError）。分开跑。

## App Store 元数据文案（推广文本 / 描述 / 关键词）

**需求**：用户问「发布时：推广文本、描述、关键词怎么填？」

**产出**

- **新建 `docs/appstore-aso-copy.md`** —— 三字段可直接复制的文案 + 字符计数 +
  写作依据 + 注意事项（这是文案的权威页，以后改文案改这里）。
- **新建 `scripts/aso_stats.mjs`** —— 词库规模统计。**为什么要真跑**：教材线由
  `curriculum.ts` 运行时派生（`applyKebiaoTo` 会 splice 课标单元），读源码数字必然偏小。
  去重口径按**原样文本区分大小写**（同 audio.ts 查表口径，IT/it 不能合并）。
- **清理 `docs/ios-appstore-release-guide.md` 两处过时内容**：§3.1 关键词行（原来只列 7 个词、
  只占 30 字符，纯浪费）、§3.4 旧描述文案（写于「只有三套教材、1600+ 词条」时期，
  与现状 6 套教材 / 654 单元不符）。两处均改为指向新页。

**量出来的事实（`scripts/aso_stats.mjs`）**

| 项 | 数值 |
| --- | --- |
| 教材线 | 6 条 |
| 单元 | 654 |
| 词条（各线累加） | 18001 |
| **跨 6 线去重后** | **5491**（单词 3539 + 短语 1484 + 句子 468） |
| 美音 / 英音 mp3 | 6108 / 6108 |
| 电影台词 | 102 条 / 79 部影片 |

⇒ **对外宣传统一用「654 个单元、5000+ 词条」**（用去重后的 5491，不用累加的 18001）。

**⚠️ 本轮最有价值的发现：Apple 自己的文档对关键词上限自相矛盾**

- 《创建产品页》搜索指南写 **100 characters**；
- 《平台版本信息》帮助文档写 **100 bytes**。

中文 UTF-8 一个字 3 字节 ⇒ 两种口径差 3 倍（100 字节 ≈ 33 个汉字）。
**判断按字符**，理由：若「30 字节」口径为真，副标题就只能写 10 个汉字，
而 App Store 上中文 App 的副标题普遍超过 10 字 ⇒ 该表述与平台实际行为不符。
中文 ASO 教程给的示例也都是 40–50 字符级别。
**做法**：主推 87 字符版，另备 30 字符 / 76 字节的兜底版（两种口径都过），ASC 报超长就换。

**文案策略（分工，别互相抢词）**

| 位置 | 权重 | 本次安排 |
| --- | --- | --- |
| App 名称 | 最高 | `安妮英语听写`（6 字符，不改） |
| 副标题 | 第 2 | `人教版外研社教材同步 · 单词听写拼写`（19 字符）⇒ 把两个教材品牌词放这 |
| 关键词 | 高 | 87 字符，**只补名称/副标题没有的词**（Apple 把三处组词后统一索引，重复=浪费） |
| 推广文本 | **不参与搜索** | 只写「最近更新了什么」；**随时可改、不用提审** ⇒ 教材线更新只改这里 |
| 描述 | 间接（给网页搜索引擎） | 697 字符；前 3 行放最大价值（搜索结果只露前面） |

**其他硬事实**

- **首版没有「新功能 / What's New」字段**，第二个版本起才有。
- 描述**纯文本、不支持 HTML**，换行符可用。
- 关键词**每个词至少 2 字符**，**不得含其他 App/公司名**（填竞品名是违规的）。
- 关键词逗号后**不要加空格**（空格也占额度）。
- 措辞红线见新页 §3：别写「儿童专属 / For Kids」（指南 2.3.8，进 Kids 类目不可逆）、
  别写绝对化用语（中国《广告法》）、别暗示官方授权（指南 5.2.1）。

**「免费」的写法留了活口**：文案用「免费使用」而非「完全免费」，因为
`docs/iap-readiness.md` 已评估过上架后加内购（约 2-4 天工作量），
而**改描述要跟着提审** ⇒ 先留余地。若确定永不加内购，可换成「完全免费」提升转化。

## 年龄分级（Age Rating）

**需求**：用户问「年龄分级需要设置吗？怎么设置？」

**核实到的关键事实（2026-09-17）**

- 年龄分级是**必填**项。Apple 原文：*required app information property*，
  且 **Unrated 的 App 不能上架 App Store**。
- ⚠️ **Apple 2026 年换了新分级体系**：**4+ / 9+ / 13+ / 16+ / 18+**
  （旧的 **12+、17+ 已取消**；2025 年 7 月随 iOS 26 beta 公布）。
- **所有 App 都要重填新问卷**，Apple 给的截止日是 **2026-01-31**，
  逾期「App 更新不再被接受」。现在已过 ⇒ **新 App 首次提交必然走新问卷**，
  没有"沿用旧分级"这条捷径。
- 问卷三类：**内容描述符** + **App 内控制** + **能力**，每项按**频率**答（无 / 偶尔 / 频繁）。
- 分级**因地区而异**（澳、巴、越、韩有地区特定值）。**只能往更严调，不能往更松调**。
- **Made for Kids 一旦通过审核不可更改**（与 Bundle ID 同级慎重）——见下面第 3 点。

**⚠️ 本项目分级判定 ⇒ 4+（全部为「无」）**，依据均已实查：

| 类别 | 依据 |
| --- | --- |
| 无限制网页访问 | **全项目唯一网络调用**是 `src/lib/audio.ts` 读自带音频（`${BASE_URL}audio/…`）；grep 全 `src/` 无 `fetch` 外链 / `axios` / `WebSocket` / `EventSource` / `geolocation` |
| App 内购买 | `entitlement.ts` 仅预留，`docs/iap-readiness.md` 明确未接入 |
| 用户生成内容 / 社交 | 无后端、无分享入口；排行榜是**本机多用户**数据 |
| 粗俗语言 | **102 条电影台词逐词实查**：无 damn/hell/shit 等；无烟酒毒品、无武器血腥、无性暗示 |
| 其余（暴力/恐怖/赌博/健康/广告/AI） | 均无 |

**最大的易错点**：**「无限制网页访问」是分级被推到 16+ 的头号原因**，也最容易误选。
判据是"App 内能否打开**任意**网址"。本项目无任何外链 ⇒ 选**否**。
（以后若加"帮助页/官网"这类**固定域名**展示页，性质不同，但加之前要重新如实评估。）

补入新体系、逐项判定表、操作步骤、三个易错点，并保留原有的「不加入 Kids 类目」
对比表；另加一条 Apple 原文提示（Made for Kids 不可逆）。
