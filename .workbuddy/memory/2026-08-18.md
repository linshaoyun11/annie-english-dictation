- 连通性实测结论（curl 验证）：
  - api.dictionaryapi.dev：200，~1.5s，多数词含 -us 美音真人录音 ✅
  - api.streamelements.com：可用音色仅 Joanna/Salli/Justin/Amy/Emma/Nicole/Brian（其余 401），均标准音质
  - en.wiktionary.org / upload.wikimedia.org：国内被墙（超时）❌ 不可用

- 优化方案（缓存直放优先）：
  - `audio.ts` 新增 `getCachedAudio(text)` 同步缓存查询；词典超时 2.5s→2s、TTS 4s→3s
  - `useSpeechLoop.ts`：抽出 `attachAudio(url, gen)`；`start()` 先查缓存，命中则直接播放真人音频（跳过浏览器过渡语音），未命中才浏览器语音+后台拉取
  - `LearnPage.tsx`：预取范围 1 题 → 后 3 题 + 下一单元第 1 题
  - `App.tsx`：挂载即 `primeSpeech()` 预热语音引擎；`startLearning()` 进入学习前预取第一题音频

## 音频链路重构：换真人源 + 元素级缓存（用户反馈：重复读每遍都重新载入 + 仍是机器人口音）

- **关键发现**：`api.dictionaryapi.dev/media/pronunciations/*.mp3`（真人录音文件域）稳定返回 **502 Bad Gateway**（curl 连续 3 次验证）→ 之前缓存的"真人录音 URL"全是坏的，播放失败后静默降级浏览器机器人 TTS —— 这才是口音问题真正根源
- **新音频源实测**：
  - 有道词典 `dict.youdao.com/dictvoice?audio=WORD&type=2`：HTTP 200 audio/mpeg，国内直连 ~0.12s，真人发音（apple 9837B、school 11181B、morning 26720B 等均正常）✅ 但**无 CORS** → 不能 fetch 成 blob，只能 `<audio>` 元素直接播放
  - 百度翻译 gettts：200 可用，同样无 CORS
- **audio.ts 重构**：
  - `AudioResult` 改为 `{ url, source: "youdao" | "tts", el?: HTMLAudioElement }`；`audioCache` 存 URL + 已加载元素（元素级缓存），300 条 FIFO 淘汰
  - 单词源：dictionaryapi → **有道**（`youdaoUrl()` 只留 a-z 字符，don't→dont、good-bye→goodbye 保证 URL 有效）；短语/句子仍 StreamElements Joanna（blob）
  - 新增 `ensureElement()`（预取即创建元素+加载，数据提前下载）、`fallbackToTTS()`（有道播放失败自动换 TTS 并更新缓存）
  - `resolveAudio` 单词不再等网络查询（直接返回有道 URL），省去词典 1.5s
- **useSpeechLoop.ts**：`attachAudio` → `attachCached(result, gen)`：复用缓存的元素；`readyState>=2` 直接播，否则等 `canplay`；`error` → 有道降级 TTS → 再失败 Web Speech；4s 加载超时兜底
- **效果**：同一单词整场会话只下载一次，循环重读（onended→3s→playOnce 复用元素 currentTime=0）与切回该单词均为内存播放，零网络请求
- 构建通过（tsc + vite，产物 index-Cyg5_4pL.js 299.98 kB）

## 修复：单词重复加分 bug（用户反馈"学一个单词得 10 分"）

- **根因**：`SpellingInput.pushLetter` 在 `setTyped` 的 **updater 函数内部**调用了 `onComplete()`（副作用）。入口 `main.tsx` 包了 `<StrictMode>`，React 18 开发模式会双调用 state updater 检测副作用 → `onComplete` 触发两次 → `LearnPage.markComplete` 跑两次；而 markComplete 用闭包旧 `progress` 判断 isFirstTime，两次都为 true → 单词 5+5=10 分（同理 phrase 8→16、sentence 10→20）
- 注：生产构建（npm run build）无 StrictMode 双调用，打包版只加一次；用户一直在用 dev 服务器所以一直遇到
- **修复 1（SpellingInput.tsx）**：onComplete 移出 updater，改用 `useEffect` 监听 `typed.length===totalLetters` 且全部正确时触发；`completedRef` 守卫确保只调一次；揭示（"我不会"）时设 `completedRef=true` 阻止误触发 onComplete（揭示不加 分）
- **修复 2（LearnPage.tsx）**：`markComplete` 加 `awardedRef`（Set）双保险，同一题 id 只加一次分；依赖数组移除 `progress`（改用 ref+函数式更新），markComplete 更稳定
- 积分规则确认无误：word 5 / phrase 8 / sentence 10（`pointsForEntry`）；词库扫描无"单词误标 sentence"的异常条目（仅 `hard-working` 标 phrase 合理；`hot dog`/`living room`/`ice cream` 标 word 合理）
- 历史积分偏高是此 bug 造成的（dev 模式下翻倍），用户可酌情重置
