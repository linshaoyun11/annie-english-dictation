## 构建失败排障（签名证书步骤）

- 报错 `Cannot save Signing Certificates without certificate private key`：根因是 `fetch-signing-files --create` 创建发布证书时需要提供 `CERTIFICATE_PRIVATE_KEY` 环境变量（2048 位 RSA PEM 私钥，嵌入生成的发布证书），未提供则保存证书失败。
- 修复：本地 `ssh-keygen -t rsa -b 2048 -m PEM` 生成私钥（存 `.workbuddy/ios-cert-private-key`，已加 .gitignore），用户需在 Codemagic App 设置 → Environment variables 创建 **code-signing** 变量组并录入 `CERTIFICATE_PRIVATE_KEY`（勾选 Secure），codemagic.yaml 已加 `environment.groups: [code-signing]`（提交 cc9962c）。
- 关键知识点：Codemagic 自动签名三要素——App Store Connect API 集成（密钥）、CERTIFICATE_PRIVATE_KEY（证书私钥）、fetch-signing-files --create；yaml 引用网页端变量必须通过 environment.groups 引用变量组名。
- 签名环节已通过（用户成功录入私钥后）。追加了一层快速失败检查：脚本开头检测 `$CERTIFICATE_PRIVATE_KEY` 为空则打印中文诊断提示退出，避免含糊的同名报错（提交 790eecb）。

### 诊断：冷启动学习页音频卡死+页面卡顿（用户 23:24 反馈，待修复）

- 注意：build 9 的 applicationDidBecomeActive + interruption observer 又加了更多主线程同步 setActive，装到 build 9/10 只会加重。
- 修复方向：setCategory 留主线程（非阻塞）；所有 setActive(true) 统一走 DispatchQueue.global 后台队列；启动预热改异步调用。

### 修复学习进度恢复异常（commit cbf33d1，APP_BUILD 12）
- 现象：首页显示小学3年级当前单元 10/10，点击进入学习页仍是第1单元第1个词（1/10）。
- 根因：
  1. `startLearning` 直接信任 `progress.entryIndex` / `gradeProgress` 保存的下标，没有跳过已完成题目。当上一会话完成单元后未点祝贺页"继续学习"就回首页/杀进程，指针停留在已完成单元；下次从年级卡片进入会落在 index 0，显示 1/10。
  2. `storageSet` 对原生 Preferences 是 fire-and-forget，App 被杀时若异步写入未完成，下次冷启动 `recoverStorage` 可能恢复旧的 native 快照，把 `entryIndex` 回退。
  3. `LearnPage` 同步 `gradeProgress` 时用 `saved.unitOrder === prev.unitOrder` 引用比较，每次新 progress 对象都触发无意义重写。
- 修复：
  - `App.tsx startLearning`：无论"继续学习"还是年级卡片，都先跳过已完成的题目；当前单元全完成则向后查找第一个有未学题目的单元；全部学完才从头复习。
  - `storage.ts`：跟踪 `pendingNativeWrite`，暴露 `flushStorage()`；`App.tsx` 在 `visibilitychange hidden`（切后台）时 flush，降低 iOS 杀进程回退概率。
  - `LearnPage`：`gradeProgress` 同步去掉 `unitOrder` 引用比较，只比较 `unitIndex`/`entryIndex`。
- tsc 通过，已推送 origin/main；需 Codemagic Start new build（build 12）后 TestFlight 验证。
