## 外研三起 G7-G9 音频 100% 覆盖（含 id 算法 bug 修复）

按用户指示"先处理外研初中段音频缺口"，从 audit 出发逐项排查 → 发现两处 bug →
修复 + 重跑 + 清理，最终 App 端 1365/1365 词条都能播放。

### 1. 真因诊断：parse_waiyanshe 的 id 算法陷阱

外研三起 G7-G9 共 1365 词条 / 1299 unique text，按 App 端播放路径审计：
- 美音 168 unique / 英音 208 unique 没有 manifest 键 → App 端漏播

第一次实跑只成功 56+20 个文件 + manifest，与 audit 报的 168/208 差距巨大。根因：
**`parse_waiyanshe` 把 G3-G6 的 `n += 1` 跳过了**（`if not (7 <= g <= 9): continue; n += 1`），
但 `mk.ts` 的 `prefixSeqs` 是**全文件全局递增**。结果 junior high 算出 `wy-g7u0e0005`
而非真实的 `wy-g7u0e1188`。

**修复**：`parse_waiyanshe` 中 `n += 1` 必须在 grade 过滤**之前**（n 永远累计，仅过滤写入）。

### 2. 真因诊断：manifest 没写入（断点续传 A 跳过污染）

修了 id 后第二次实跑仍只 +1 manifest 键。根因：
- 实跑**确实**生成了文件（如 wy-g7u0e1188.mp3 存在且合格）
- 但因为同时修了 id，旧的"错 id 文件"（wy-g7u0e00xx.mp3）也存在
- 第二次实跑 collect_gaps 走 A（自己文件已合格）跳过 → 不调 update_manifest
- 结果：文件有了，但 manifest 不指向 → App 端仍漏播

**修复**：新增 `scripts/fix_waiyanshe_manifest.mjs`
- 解析 waiyanshe.ts 得 (id, text) 对
- 对每个 unique text，若文件存在且 man[text] 未写入 → `man[text] = id`
- 一次性补 167 美音 + 208 英音 映射

### 3. 工具脚本沉淀

| 脚本 | 用途 |
|---|---|
| `scripts/generate_waiyanshe_g7g9.py` | 缺口生成主脚本（修 id 算法后） |
| `scripts/fix_waiyanshe_manifest.mjs` | 补 manifest 映射（修了 A 跳过问题） |
| `scripts/audit_waiyanshe_playback.mjs` | **App 端播放路径审计**（真理指标） |
| `scripts/audit_waiyanshe_gaps.mjs` | unique text 维度缺口统计 |
| `scripts/audio-pipeline.md` | 文档化"id 算法必须全局递增"教训 |

### 4. 503 个孤儿清理

修了 id 算法后，旧的"错 id 文件"（wy-g?u?e0xxx.mp3 等）变成孤儿——既不在新生成的 valid_ids
中，也不在 manifest.values 中。一次性脚本 `_cleanup_wy_orphans.py` 清掉 503 个 / 6.5 MB
磁盘占用（保留人教版 g-/ra- 各自清理）。

### 5. 教训（写进 audio-pipeline.md）

- **id 算法的全局性陷阱**：解析任何教材 .ts 时，id 中的 `n` 必须按 mk 调用顺序**全局**递增，
  不能按 grade/unit 过滤后再递增。否则所有 id 错位，文件落在 id=0xxx 的"假 id"，
  App 端查 manifest(text) 找不到（正确的 id 是 1xxx+）。
- **App 端路径审计 vs file-level audit 是两件事**：file 存在 ≠ App 能播。
  `manifest(text) → id → file` 才是播放路径，需同时满足三个条件。
