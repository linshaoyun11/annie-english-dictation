## ⚠️ 操作教训：推送后不要单独 commit+push 文档补记

本次推送 build 55 后，我又补写了 memory 并 `git add -A && git commit && git push`。
差点造成两个问题：

1. **多跑一次 Codemagic 构建** —— `codemagic.yaml` 无 `triggering`，任何 push
   即触发，且 `APP_BUILD` 仍是 55。
2. **更严重：build 号相同 → App Store Connect 上传失败**（版本重复被拒），
   用户会看到一次红色构建失败，误以为是代码问题。

**正确做法**：memory 补记必须在**推送之前**写完，与代码改动一起提交。
若已经推完了才发现漏写，就把它留在工作区（未暂存），攒到下次代码改动一起推。
（这条是项目既有惯例的强化版，之前只说"纯文档 commit 攒着推"，

## ⚠️ git reset --soft HEAD~1 的坑（本次踩到）

想撤销"刚做的本地 commit"时用 `git reset --soft HEAD~1` —— 但**如果那个 commit
已经推送到远程了**，HEAD~1 会指向远程已有的上一个 commit，等于把已推送的内容
也一起撤回来，本地瞬间落后远程一个 commit。

**恢复方法**：`git reset --soft <已推送的那个 commit>`（如 `git reset --soft cc753f0`），
HEAD 回到原位，改动保留在暂存区；再用 `git restore --staged <文件>` 把
不想提交的文件撤出暂存区（内容仍保留在工作区）。

本次恢复后最终状态：本地 HEAD = 远程 main = cc753f0，
仅 `.workbuddy/memory/2026-09-03.md` 为未暂存修改，留待下次一起推。

### 关键事实（与直觉不符，勿忘）

### 踩到的坑

1. **`node -e "..."` 里写含 `\\` 的正则必炸**（bash 吞反斜杠 → `Unterminated regexp literal`）。
   一律写成 `.mjs` 文件再跑。本会话踩了两次。
2. **`grep -c` 对压缩后的单行 JS 只返回 0/1**，判断"是否入包"必须用 `grep -o X | wc -l`。
3. **`ra-` 在产物里搜不到是正常的**：id 由模板字符串拼接，字面量只有 `"ra"`，`-g` 是拼出来的。
4. **`esbuild` 不在 package.json 里**（`npx esbuild` 会临时联网拉）；项目本地有的是
   **rolldown**（Vite 8 打包器）。脚本里转译 TS 应 `import { build } from "rolldown"`。
5. **rolldown 的 `logLevel` 不接受 `"error"`**（只收 debug|info|warn|silent），传了抛
   `Unexpected log level`。
6. **Windows 下 `execFileSync("npx", ...)` 必 ENOENT**（npx 本质是 .cmd，要 `shell:true`）。
7. 脚本放项目根时 `import("../x.mjs")` 会解析到**上层目录**，必须用
   `pathToFileURL(join(process.cwd(), f)).href`。
8. **`KEBIAO_BANK` 的字段名是 `en` / `ph` / `cn` / `band`**，不是 `english`。
