## 1. 硬性前提与当前项目差距

### 1.1 必须准备的硬件

| 项目        | 说明                                                    | 状态    |
| --------- | ----------------------------------------------------- | ----- |
| Mac 电脑    | **非必需**。首选云 CI（方案 B，¥0）；其次租用云 Mac；最后才是购买（见下方替代方案） | ☐ 已有替代方案 |

| Apple ID  | 开启双重认证                                                | ☐ 未就绪 |

**没有 Mac 的替代方案（按推荐顺序）：**

1. **云 CI 自动构建（推荐，¥0）**：Codemagic 免费额度 500 分钟/月，一次 iOS 构建约 15-25 分钟，足够首次发布+多次迭代。本项目已配好 `codemagic.yaml`（含图标注入、版本号、竖屏配置、自动传 TestFlight），**详细步骤见 `docs/capacitor-ios-setup.md` 第三节「方案 B」**。同类服务还有 Capgo Build、Capawesome Cloud（付费）；
2. **云 Mac 服务**：MacStadium、MacinCloud、腾讯云/阿里云 Mac mini 实例，约 $40-80/月，适合想手动操作 Xcode 但不想买硬件的场景（约 ¥500-1500/次发布）；
3. **第三方代打包服务**：把 Web 包交给上架服务商打包（约 ¥300-1000 一次），但证书仍需要你自己的 Apple 开发者账号。

> **关于 iPad**：iPad 无法运行 Xcode，不能承担打包签名工作；但 Safari 浏览器可以完整操作 App Store Connect（建 App、填元数据、提审、回复审核意见），TestFlight 装在 iPad 上还是很好的真机测试渠道（顺便验证大屏布局）。
>
> 建议：如果后续要长期迭代（安卓+iOS 双端），值得认真考虑一台二手 Mac mini（M 系约 ¥3000-4000 二手）；只发这一款 App，云 CI 完全够用。

## 2. 阶段 0：账号与资质准备（建议立即开始，周期最长的先办）

### 2.1 Apple Developer 开发者账号

**账号类型对比：**

| 类型              | 年费            | 适用      | 备注                             |
| --------------- | ------------- | ------- | ------------------------------ |
| 个人 Individual   | $99（约 ¥688）   | 独立开发者   | 卖家名称显示个人姓名；24-48 小时激活          |
| 公司 Organization | $99（约 ¥688）   | 团队/公司   | 需邓白氏编码（D-U-N-S），审批 1-2 周；显示公司名 |
| 企业 Enterprise   | $299（约 ¥2077） | 仅内部测试分发 | **不能上架 App Store**             |

**注册步骤：**

1. 访问 <https://developer.apple.com/programs/enroll/> ，用 Apple ID 登录（需已开启双重认证）；
2. 填写个人信息：姓名、地址、电话（公司账号还需邓白氏编码）；
3. 选择账号类型 → 支付 $99（支持 Visa/Mastercard 等国际信用卡）；
4. 等待激活：个人 24-48 小时，公司 1-2 周。

> 建议：先用**个人账号**起步（可随时升级为公司账号，App 不丢失）。如果 App 未来以机构/学校名义发布，则一开始就注册公司账号。

### 2.2 软件著作权（软著）—— 并行申请

- **苹果 App Store 不强制要求软著**，但教育类 App 在审核中对原创性存疑时可能被要求提供证明；
- **国内安卓市场（华为/小米/应用宝等）普遍强制要求软著**——反正迟早要办，建议现在就申请，与 iOS 发布并行推进；
- 申请主体：个人或公司均可；
- 材料：源代码（前后各 30 页）、用户手册/操作说明、申请表；
- 周期：普通 30-60 个工作日，加急 15-30 天（代理）；
- 费用：官方约 ¥300，代理服务约 ¥500-2000；
- 注意：软著名称建议与 App 名称一致或高度相关（如「安妮英语听写软件」），安卓商店会核对名称与包名一致性。

### 2.3 商标注册（可选但推荐）

- App 名称「安妮英语听写」若计划长期运营，建议注册第 9 类（软件）与第 41 类（教育）商标；
- 国内商标普通申请约 ¥300/类/件，周期 6-12 个月；**早申请可以早锁定名称**（App Store 名称是先到先得，若名称被抢注同名 App 可能被投诉下架）。

### 2.4 域名与网页托管

需要两个可公开访问的 URL（苹果强制要求，审核必查）：

1. **隐私政策 URL**：说明数据收集情况（我们几乎不收集，内容很简单）；
2. **技术支持 URL**：一个能联系到你的页面（邮箱/联系方式）。

> 低成本方案：GitHub Pages / Vercel / 腾讯云静态托管，放一个简单的静态页面即可；也可做一个小官网（介绍 App + 下载引导 + 隐私政策 + 支持邮箱），后续安卓上线也能用。

## 4. 阶段 2：Capacitor 集成与 iOS 打包（需在 Mac 上执行）

### 4.1 环境要求（2026 年 8 月核实）

| 组件        | 要求                                                                       |
| --------- | ------------------------------------------------------------------------ |
| macOS     | 最新正式版（可装 Xcode 26）                                                       |
| Xcode     | **26.0 及以上**（2026-04-28 起苹果强制：提交 App Store 必须用 Xcode 26 / iOS 26 SDK 构建） |
| Node.js   | 22+（当前项目 Node 22.22.2 ✅）                                                 |
| CocoaPods | Capacitor 8 默认改用 Swift Package Manager，可不装                               |

### 4.2 集成步骤

在项目根目录（Windows 上开发完推代码，Mac 上拉取后执行）：

```bash
# 1. 安装 Capacitor 8（核心 + CLI + iOS 平台）
npm install @capacitor/core @capacitor/cli @capacitor/ios

# 2. 初始化配置（生成 capacitor.config.json）
npx cap init "安妮英语听写" "com.annie.dictation" --web-dir=dist

# 3. 构建 Web 资源
npm run build

# 4. 生成 iOS 原生工程
npx cap add ios

# 5. 每次改完 Web 代码后同步到原生工程
npm run build && npx cap sync ios

# 6. 打开 Xcode
npx cap open ios
```

### 4.3 Xcode 内配置（App.xcodeproj）

| 配置项               | 位置                             | 值                                           |
| ----------------- | ------------------------------ | ------------------------------------------- |
| Display Name      | General → Identity             | 安妮英语听写                                      |
| Bundle Identifier | General → Identity             | com.annie.dictation（与 App Store Connect 一致） |
| Version / Build   | General → Identity             | 1.0.0 / 1                                   |
| Deployment Target | Build Settings                 | iOS 15.0+（覆盖绝大多数存量机型）                       |
| 图标                | Assets.xcassets → AppIcon      | 放入 1024×1024 图（自动生成全尺寸）                     |
| 启动屏               | Assets.xcassets → LaunchScreen | Capacitor 默认已配置，可自定义品牌色/Logo                |

### 4.4 包大小评估（针对本项目）

| 项                | 大小           | 结论                         |
| ---------------- | ------------ | -------------------------- |
| 音频（public/audio） | 114 MB       | 进入 IPA                     |
| 代码 + 资源          | 约 5-10 MB    | —                          |
| 预估 IPA（压缩后下载大小）  | 约 110-130 MB | **低于 200MB 蜂窝下载上限 ✅ 无需拆分** |

即使不拆包，用户用流量也能直接下载（>200MB 才会被 iOS 拦截要求连 Wi-Fi）。后续若体积继续膨胀，可再考虑苹果 On-Demand Resources（按需下载）或按年级分包。

## 5. 阶段 3：证书与签名（Xcode 自动签名，几乎零操作）

1. Xcode → 项目 → Signing & Capabilities → 勾选 **Automatically manage signing**；
2. Team 选择你的开发者账号（首次需在 Xcode → Settings → Accounts 登录 Apple ID）；
3. Xcode 自动创建并管理：App ID、Distribution 证书、Provisioning Profile。

> 个人开发者不需要手动管理证书；只有 CI/CD 自动化或多人团队才需要手动签名或 Fastlane Match。证书有效期 1 年，自动签名会在到期前自动续。

## 6. 阶段 4：App Store Connect 后台配置

入口：<https://appstoreconnect.apple.com> → 我的 App → 右上角「+」→ 新建 App

### 6.1 基础信息

- 平台：iOS；
- 名称：安妮英语听写；
- 主要语言：简体中文；
- 套装 ID（Bundle ID）：com.annie.dictation；
- SKU：ANNIE2026V1。

### 6.2 定价与销售范围

- 价格：免费（或自定价格层级）；
- 销售地区：默认全球可用；若仅面向中国大陆，可只勾选中国区；
- **中国区上架额外注意**：苹果中国区对教育类 App 一般不要求额外资质（不同于安卓市场），但若 App 内出现付费课程/直播等内容则需相应许可证——我们的纯工具型听写 App 不受影响。

### 6.3 类目与年龄分级

- **主类目：教育（Education）**；
- 年龄分级问卷：按内容如实勾选 → 自动得出 **4+**（无暴力/色情/赌博/毒品等，纯学习工具必然 4+）；
- **是否加入 Kids 儿童类目？——建议不加入**：

| 对比    | 不加入 Kids（推荐）         | 加入 Kids                                             |
| ----- | -------------------- | --------------------------------------------------- |
| 额外要求  | 无                    | 需家长门（parental gate）、禁止第三方分析/广告、年龄档（5- / 6-8 / 9-11） |
| 元数据措辞 | 避免「儿童专属」等字眼，用「中小学英语」 | 可明示「For Kids」                                       |
| 适合    | 小学~初中年龄段通用           | 明确针对 12 岁以下儿童                                       |

> 折中说明：即使不加入 Kids 类目，因为面向未成年人，苹果仍会依据 5.1.4 检查——我们**不收集任何个人信息、无广告、无外链**，正好天然满足 COPPA/GDPR-K 的合规要求，这是最大的加分项。

### 6.4 隐私标签（Privacy Nutrition Labels）

- 在「App 隐私」页面如实申报；
- 我们的 App：**不收集数据（Data Not Collected）**——因为无账号、无分析、无广告 SDK，数据全在本地；
- 这是所有选项里最干净的声明，审核最快、最不易被卡。

### 6.5 其他必填项

- 描述、关键词、截图、App 图标（见阶段 1）；
- 技术支持 URL、隐私政策 URL（见阶段 0.4）；
- 版权信息：© 2026 你的名字/公司名；
- 审核备注（可选）：可留言说明「数据仅存本地、无账号、无广告、无内购」便于审核员理解。

## 7. 阶段 5：TestFlight 内测（强烈建议，必做）

1. 在 Xcode 中 Archive 并上传到 App Store Connect（或 `npx cap sync ios` 后 Product → Archive → Distribute App → App Store Connect）；
2. 登录 App Store Connect → TestFlight → 等待构建处理（15-30 分钟）；
3. 添加测试人员：
   - 内部测试：最多 25 人，无需审核，即时可用；
   - 外部测试：最多 10000 人，需一次简单审核（约 1 天）；
4. 测试人员用 TestFlight App 安装，**至少覆盖：iPhone SE / 主流 iPhone / Pro Max 三种尺寸 + iOS 15/16/17/18 各一档系统**，重点验证：
   - 音频播放（美音/英音、离线、无卡顿）
   - 学习进度保存（杀进程重进、多用户切换）
   - 键盘输入、听写流程
   - 首启加载性能、冷启动速度

> TestFlight 是正式审核前的最后一道防线，能提前发现真机环境问题，务必完成这一轮再提交正式审核。

## 8. 阶段 6：提交正式审核

### 8.1 提交流程

1. App Store Connect → 你的 App → 选择已上传的构建版本；
2. 确认所有元数据完整（描述/截图/隐私政策/支持 URL 等）；
3. 点「提交审核」→ 回答出口合规问卷（加密等，如实选否/无）→ 提交；
4. 等待审核：通常 1-3 个工作日；通过后可选「自动发布」或「手动发布」。

### 8.2 针对本 App 的常见被拒风险与预防

| 风险点              | 预防措施                                                                        |
| ---------------- | --------------------------------------------------------------------------- |
| 截图与 App 实际不符     | 用模拟器真实截图，不修图夸大                                                              |
| 崩溃/闪退            | 先跑完整 TestFlight 轮次；重点测音频播放与存储边界                                             |
| 隐私政策缺失/不合格       | 提前把隐私政策挂到可访问 URL                                                            |
| 元数据含「儿童/小学生专属」暗示 | 未加入 Kids 类目时，描述用「中小学英语」等措辞                                                  |
| 音频版权问题           | 语音由有道/百度 TTS 合成，属工具生成；若审读员问询，说明来源。若担心，可替换为开源 TTS（如 edge-tts）重新生成（注意后续版本一致性） |
| 教材内容版权           | 词表来自人教/外研社/牛津课标词汇（词汇表本身属教育公开内容），描述中写「同步教材词汇」一般无碍；避免在 App 内直接展示教材原文/扫描页      |

### 8.3 审核被拒后

- 在 App Store Connect → 解决方案中心（Resolution Center）回复苹果的拒绝理由；
- 常见处理：补充说明、修改后重新提交（重审通常 1-2 天）；
- 保持冷静，逐条回复，多数问题 1-2 轮内可解决。

## 9. 阶段 7：正式发布与后续

### 9.1 发布

- 审核通过后，在 App Store Connect 选择「手动发布」并点击发布按钮，或等「自动发布」生效；
- 上架后 1-24 小时在全球各商店页可见。

### 9.2 版本更新（迭代循环）

1. Xcode 中递增 Version（如 1.0.1）与 Build 号；
2. `npm run build && npx cap sync ios` → Archive → 上传；
3. 新构建上传后会自动进入 TestFlight，验证后提交审核；
4. 注意：每次提交都需满足 Xcode 26 构建要求（保持工具链最新）。

### 9.3 运营建议

- 监控 App Store Connect 的数据（下载量、留存、崩溃、评分）；
- 收集用户反馈，规划版本迭代；
- 尽快拿到一定量真实好评（评分影响搜索排名）。
